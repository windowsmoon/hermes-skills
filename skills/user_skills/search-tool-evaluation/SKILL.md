# 搜索工具评估框架

## 评估维度（6 个维度打分）

对任何新的搜索工具/数据源，按以下 6 个维度逐一评估：

### 1. 覆盖范围
- 工具能搜哪些内容？
- 是否覆盖我们目前没有的数据源？
- 示例：AgentKey 覆盖微博/微信/B站/抖音（我们没有）

### 2. 深度 vs 宽度
- 是深搜单一平台，还是浅搜多个平台？
- 示例：zhihu-search 深搜知乎（含直答）> AgentKey 浅搜知乎

### 3. 免费额度
- 免费额度是多少？是否够日常使用？
- 示例：zhihu-search 5,000次/天（够用），AgentKey 付费（不够经济）

### 4. 接入成本
- API / MCP / CLI / Skill？哪种接入方式？
- 是否需要额外注册、认证、付费？
- 示例：Codex Skill Universe 是本地 Web UI，不能直接 Agent 调用

### 5. 与现有工具的重叠度
- 与现有 10 个搜索工具有多少重叠？
- 重叠部分，谁更强？
- 评估表：见 references/evaluation-matrix.md

### 6. 维护成本
- 是否需要维护 Token、Server、账号状态？
- 稳定性如何？会不会突然挂掉？

## 决策流程

```
评估新工具
    │
    ├─ 有独特覆盖？→ 是 → 继续
    │              否 → ❌ 不装
    │
    ├─ 独特覆盖我们强？→ 是 → ❌ 不装（已有平替）
    │                   否 → 继续
    │
    ├─ 免费 or 低成本？→ 是 → 继续
    │                   否 → ❌ 不装（或留作备选）
    │
    ├─ 接入成本低？→ 是 → ✅ 装
    │               否 → ⚠️ 观望
    │
    └─ 维护成本低？→ 是 → ✅ 装
                    否 → ⚠️ 观望
```

## 已评估工具清单

### AgentKey（2026-07-22 评估）
- **结论：不装**
- **原因：** 重叠部分（网页搜索/知乎/小红书）我们更强；缺失部分（微博/B站/抖音/微信）有平替
- **评分：** 覆盖 6/10，深度 4/10，额度 N/A（付费），成本 5/10，重叠 8/10，维护 5/10

### Codex Skill Universe（2026-07-22 评估）
- **结论：不装**
- **原因：** 是本地 Web UI 管理工具，不是 API/MCP，不能被 Agent 调用
- **评分：** 覆盖 0/10（非搜索工具），用途不同

### zhihu-search（2026-07-22 安装）
- **结论：已装**
- **原因：** 知乎站内搜索深度远超通用搜索，直答功能独一无二
- **评分：** 覆盖 8/10，深度 10/10，额度 9/10，成本 8/10，重叠 3/10，维护 8/10

## 当前搜索体系架构

```
中文搜索（3路并行）
  ├─ open-webSearch  → 百度/Bing 通用网页
  ├─ AnySearch       → 结构化+22垂直领域
  └─ zhihu-search    → 知乎社区经验+直答

英文搜索（2路并行）
  ├─ Tavily          → AI 搜索 API
  └─ Exa             → 语义搜索

热点监控
  └─ TrendRadar      → 8平台聚合

专业垂类
  ├─ SenseNova系列   → 学术/代码/财经/社媒/图片
  ├─ xhs-cli         → 小红书完整客户端
  └─ Tabbit          → 反爬浏览器
```

## 常见评估陷阱

1. **被"多平台聚合"迷惑** — 聚合 ≠ 每个都好用，深度比宽度重要
2. **忽视直答能力** — zhihu-search 的直答=知乎大模型总结，比搜索更省 Token
3. **重复造轮子** — 已有 10 个工具，新工具必须有独特价值
4. **忽略维护成本** — Token 过期、Server 挂掉、API 变更都是成本
