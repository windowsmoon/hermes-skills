# Markdown 格式规范

EdrawMind API 要求输入为结构化 Markdown。以下是精确的格式规则和层级映射。

## 核心规则

| 输入格式 | 映射到思维导图 |
|---------|--------------|
| `# 标题` | 根节点（中心主题），建议仅一个 |
| `## 标题` | 一级分支 |
| `### 标题` | 二级分支 |
| `#### 标题` | 三级分支 |
| `- 列表项` | 子节点 |
| `  - 缩进列表` | 更深层子节点 |
| `1. 列表项` | 子节点（与 `-` 等价） |

## 必须满足的条件

1. **至少一个标题**（`#` 或 `##`）
2. **至少一个列表项**（`-` / `*` / `+` / `1.`）
3. 仅一个 `#`（根节点），如果有多个 `#`，仅第一个生效

## 节点文字长度建议

| 语言 | 建议字数 | 示例 |
|------|---------|------|
| 中文 | 3-10 字 | `机器学习` |
| 英文 | 3-5 词 | `Machine Learning` |

## 层级深度限制

- 建议最大深度：**5 层**
- 建议最大节点数：**~150 个**
- 超大文档建议按章节拆分

## 格式注意事项

1. **去除编号前缀**：`1. 明确指令` → `明确指令`（节点自动排序）
2. **不要用 markdown 表格**：表格不会被解析为树状结构
3. **不要用代码块**：代码块内容会被忽略
4. **不要用空标题**：`##` 后面必须有文字
5. **相同缩进 = 同级**：保持缩进一致

## 示例

```markdown
# Loop Engineering
## 基础概念
- 以前写 prompt 让 AI 回答一次
- 现在设计自动循环让 AI 自主干活
## 技术演进
- 脚本驱动
  - while 循环 + 管道符
  - 粗糙但能用
- Hook 驱动
  - StopHook 拦截机制
  - 模型既是运动员又是裁判
- 标准命令
  - Go 命令统一驱动
  - 大模型干活小模型检查
## 六大组件
- Automation
- Skills
- MCP
- Sub Agent
- Worker
- State / Memory
```

```markdown
# 项目架构
## 前端
- React
- TypeScript
- Tailwind
## 后端
- Python
- FastAPI
- PostgreSQL
## 部署
- Docker
- Kubernetes
- CI/CD
```
