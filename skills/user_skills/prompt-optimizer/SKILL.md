# 提示词优化器 (Prompt Optimizer)

## 触发方式

你在对话中说以下任意一句，自动触发优化流程：

> "帮我优化提示词：XXX"
> "优化这个提示词：XXX"
> "帮我写一个更好的prompt：XXX"
> "优化prompt：XXX"

## 工作流程（用户确认的规范流程）

```
用户: "帮我优化提示词：写一篇关于AI的文章"
  ↓
0️⃣ 需求澄清（Grill） ← 先不急着优化，做风险排查
    → 分析当前 prompt 是否存在以下三类风险：
      □ 方向偏了：用户的实际需求和 prompt 表达的不一致
      □ 意图模糊：用户没说明白真正要什么效果
      □ 边界不清：约束条件、输出格式、质量标准未知
    → 如果存在风险 → 追问，直到风险排除
    → 如果边界已经清晰 → 跳过，直接进入 Phase 1
    → AI 自行判断何时终止，不需要追到"用户烦了"为止
  ↓
1️⃣ 优化 → 我调用 prompt_optimizer.py (user模式)
    输出格式：
      ## 优化后的提示词
      [LLM 原始返回的完整提示词 — 不改写、不概括、不重新组织]
      ## 优化说明
      [改进什么 / 为什么改 / 预期效果]
  ↓
2️⃣ 用户审查 → 用户看到原始输出后给出修改意见
    "第二段再改一下，增加技术要求"
  ↓
3️⃣ 迭代 → 我调用 prompt_optimizer.py (iterate模式)
    基于用户反馈迭代新版本
  ↓
4️⃣ 执行 → 用户说"好了"、"执行吧"、"就这样"
    我使用最终确认的提示词执行任务
```

**关键规则（必须遵守）：**

0️⃣ **Phase 0 行为规则（需求澄清阶段）：**
   - 不急着优化，**先做风险排查**。分析 prompt 是否存在方向偏了、意图模糊、边界不清三类风险
   - 追问要**精准、高效**。不要为了问而问——确认一个风险排除一个，不要反复盘问同一个点
   - 风险排除了就**立即停止追问**，不要追到"用户烦了"
   - 以下四个条件全部满足时自动终止 Phase 0：
     — 理解了 prompt 的使用场景和最终目标
     — 不存在「方向偏了」的风险
     — 用户意图已经明确表达
     — 边界条件（格式/长度/风格/约束）已清晰
   - Phase 0 的追问不需要调用优化引擎，直接在对话中完成
   - 如果用户已经提供了足够的信息（prompt 本身边界清晰、目标明确），**直接跳过 Phase 0**

1️⃣ **展示原始输出** — 优化后的提示词必须展示 LLM 引擎的原始返回内容，不要用自己的话概括、改写、重新组织。用户需要看到每一个细节来判断是否满意。
   - 错误示范：我用自己话概括了3个版本 → 用户问"这个内容是怎么来的？"
   - 正确做法：直接展示## 优化后的提示词 和 ## 优化说明 的完整原始返回

2️⃣ **如果用户问"这个内容是怎么来的"** — 按步骤解释链路：你的输入 → 优化 System Prompt（告诉LLM输出优化后的提示词）→ LLM 接收 System + User → 按格式输出。必要时直接展示原始返回内容。不要只给摘要。

3️⃣ **每次迭代保留原始意图**，只根据用户反馈做调整。

4️⃣ **用户没说"好了"之前**，不要执行任务。

5️⃣ **优化说明一起展示** — 改进什么 / 为什么改 / 预期效果三段式。

## 三种优化模式

| 模式 | 命令 | 用途 |
|------|------|------|
| User Prompt | `user <原始提示词>` | 优化用户提示词 |
| System Prompt | `system <原始提示词>` | 优化系统提示词 |
| Iterate | `iterate <上次版本>` | 根据反馈迭代优化 |

## 技术实现

- 调用 custom:183399 API（deepseek-v4-flash）作为优化引擎
- 使用专用优化 prompt 模板（角色+指令+格式+示例）
- 每次迭代保留原始意图，只增强结构/清晰度/可执行性

## 输出物保存

优化完成并确认后，最终提示词会：
1. 记录到当前对话上下文
2. 执行任务时直接使用
3. 可选保存到 Obsidian
