# 用户偏好记录：展示原始输出 vs 概括

## 事件（2026-07-17）

用户要求优化提示词：`帮我写一篇朋友圈文章能驱动大家陪我一起看世界杯决赛`

**我做的（错误）：** 运行 prompt_optimizer.py user 模式后，没有直接展示 LLM 的原始返回内容，而是用自己的话概括了输出结构（"输出3个版本：版本1搞笑玩梗版…"）。

**用户反应：** "这个内容是怎么来的呢？" — 意思是"你展示的不是原始输出，你自己重新组织了一遍。"

**正确做法：** 直接展示 `## 优化后的提示词` 和 `## 优化说明` 的原始 markdown 输出，一个字不改。LLM 输出什么就给用户看什么。

## 教训

用户想看的是 LLM 引擎**实际输出了什么**，而不是 agent 对输出的概括。概括会丢失细节（比如完整的 few-shot 示例、格式要求、结构约束），用户无法判断优化质量。

## 修复

prompt-optimizer SKILL.md 已新增规则 1 和 2:
1. "展示原始输出 — 优化后的提示词必须展示 LLM 引擎的原始返回内容，不要用自己的话概括"
2. "如果用户问'这个内容是怎么来的' — 按步骤解释链路"
