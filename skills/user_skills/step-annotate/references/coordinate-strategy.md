# 坐标定位策略

vision_analyze 看到的图像是缩略图（~1024px），而原始截图可能很大（2K-4K）。
本文件记录从 vision 分析到像素坐标的换算方法。

## 通用换算公式

```
实际_x = 截图原始宽度 × (vision_x / vision看到的宽度)
实际_y = 截图原始高度 × (vision_y / vision看到的高度)
实际_w = 截图原始宽度 × (vision_w / vision看到的宽度)
实际_h = 截图原始高度 × (vision_h / vision看到的高度)
```

## Vision 提问模板

### 摸清布局（首次）
> "这张图是什么界面？顶部/左侧/底部各有什么功能区？主要操作按钮在哪里？"

### 精确定位（二次）
> "图中 [目标元素名] 按钮的文字是什么？它的左上角坐标和右下角坐标大概在什么位置？宽度和高度各占图片多大比例？"

### 相对位置
> "在截图左上角为原点(0,0)的坐标系中，[目标元素]的左上角坐标和右下角坐标分别是什么？"

## 常见 UI 元素尺寸比例参考

| 元素类型 | 在截图中通常占比 |
|---------|---------------|
| 顶部工具栏/菜单栏 | 顶部 5-8% 高度 |
| 侧边面板 | 左侧/右侧 15-25% 宽度 |
| 底部输入框 | 底部 4-8% 高度 |
| 主要按钮 | 宽度 5-15%，高度 3-5% |
| 弹窗/对话框 | 居中，约宽 40-60%，高 30-50% |
| 标签/选项卡 | 顶部 5-8% 高度区域内的水平条 |

## 避坑

1. **不要假设 vision 坐标是精确到像素的** — 它看到的图片缩放比例不同
2. **高分辨率截图（4K/2K）需要更谨慎的映射** — 小误差在原始图上被放大
3. **如果目标区域小于 30×30 像素** — vision 很难精确定位，告诉用户大致范围让用户确认
4. **包含多级菜单的截图** — 分两次 vision：先看整体布局，再看局部细节（框选子区域后单独提问）
5. **深色模式 UI** — vision 可能难以分辨深色背景上的深色元素边界，使用 contrast-enhance 复用或描述相对位置
