# Step-Annotate：批量截图编号批注

## 核心约定

> **用户画红框，Agent 加批注**

用户**不需要**：
- ❌ 给截图取名（Agent 用 vision 识别画面）
- ❌ 写标注坐标
- ❌ 在每张图下面写标注说明
- ❌ 画箭头或写编号

用户**只需要**：
- ✅ 在截图上用**红色方框**框出要标注的区域（Snipaste/微信截图都行）
- ✅ 把口播稿贴在 frontmatter 的 `口播内容:` 里
- ✅ 按层级顺序（主→子→子子）把框好的截图粘贴到模板中

## 模板位置

模板已放在 Obsidian vault：`D:/Obsidian/Note/截图标注框架模板.md`
用户直接打开使用即可。

## vision 的角色

> **vision 是验证工具，不是猜测工具**

用户已经画了红框=指明了位置，vision 只需要：
1. 确认红框位置和口播内容匹配
2. 获取画面上下文以确定标注文字
3. 在画面描述和口播步骤明显不一致时停下来问用户

不需要依赖 vision 去猜"哪里该标"——用户已经标好了。

> "帮我标注一下这个文件：D:/Obsidian/Note/截图标注框架模板.md"
> "帮我按文案标注这个路径：'...'"
> "帮我按口播稿标注 D:/Obsidian/Vedio/ 的截图"

## 工作流程

### Phase 1：读取文件

1. 读取用户给的 `.md` 文件
2. 从 frontmatter 提取 `口播内容`
3. 从正文提取所有图片引用 `![[...]]`，按出现顺序记录

### Phase 2：理解图片中的红框

对每张截图依次调用 `vision_analyze()`：
- 识别画面内容
- 找出用户画的红色方框位置
- 记录每张图上有几个红框

### Phase 3：匹配口播稿 → 红框

1. 把口播稿拆解为步骤列表
2. 按图片在 MD 中的出现顺序 + vision 识别的画面内容，匹配步骤
3. 一张图上多个红框，按**从上到下、从左到右**顺序匹配步骤
4. 如发现不匹配，停下来问用户

### Phase 4：批量处理

1. 构造 `annotations.json`，设置 `detect_boxes: true`
2. 调用 `scripts/batch_annotate.py`
3. 脚本自动：
   - 检测每张图上的红色方框（RGB 像素分析，R>180, G<100, B<100）
   - 按匹配顺序给每个红框添加编号圆 + 箭头 + 说明文字
   - **不覆盖用户画的红色方框**（keep_existing_box=true）
4. 输出文件夹：`<YYYY-MM-DD>-对<主题>的标注/`，放在 Obsidian vault 根目录
5. 文件夹名中的日期取当天，主题从口播稿提炼

### Phase 5：反馈

列出每张图的输出文件名和对应的步骤说明，问是否需要调整。

`步骤<编号>-<标注文字>.png`

例如：
- `步骤1-打开Midjourney.png`
- `步骤2-输入提示词.png`

同一张图有多个批注时，每步独立输出一张图。
多张图之间编号连续递增，不会重复。

## 多批注处理规则

同一张图上有多个红框时：
- 按从上到下、从左到右的顺序依次编号
- 编号**跨图连续递增**（第1张图的②紧接第2张图的③）
- 每个红框对应口播稿中的一个步骤
- 例如：一张图3个红框 + 口播稿连续3步 = 3张输出图

## 默认样式

- 橙色框用户已画，不再重复画
- 编号圆：白底橙字，在目标框左上外侧
- 箭头：橙色线，从编号指向目标框中心
- 说明文字：在编号右侧，橙色
- 字体：微软雅黑，16px
- 如用户有特殊要求，按指示调整

## 依赖

- Python: PIL/Pillow（Hermes 运行时自带）
- numpy（用于红框像素检测）
- 字体：Windows 微软雅黑（C:/Windows/Fonts/msyh.ttc）
- 无需额外安装

## 注意事项

1. 用户确保截图中的红框是明显的红色（RGB 中 R>180, G<100, B<100）
2. 图片必须在 Obsidian vault 内（路径以 D:/Obsidian/Note/ 开头）
3. 口播稿尽量完整，步骤顺序清晰
4. 如有多张截图内容高度相似导致匹配困难，停下来问用户
5. 红框检测算法说明见 references/红框检测技术说明.md
