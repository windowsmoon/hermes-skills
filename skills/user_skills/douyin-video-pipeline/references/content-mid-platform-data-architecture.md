# 全自动内容中台 — 数据架构方案参考

> 与 `douyin-video-pipeline` 配套的数据架构层设计。  
> 管道 skill 描述「怎么做」，本文描述「怎么度量、治理、持续运转」。

---

## 1. 全链路数据流

```
巨量百应 → Bitable(采集) → Coze(逐字稿) → LLM(分析) → OSS(图文) → Obsidian RAG → LibTV(画布) → Hermes(审批)
  L1           L2               L3              L4           L5              L6               L7
```

| 阶段 | 延迟要求 | 核心产出 |
|------|---------|---------|
| L1 采集 | ≤10min | JSON → Bitable 记录 |
| L2 逐字稿 | ≤5min | Coze 提取 → Bitable |
| L3 AI分析 | ≤3min | 结构化分析 → Bitable+OBS |
| L4 图文 | ≤60s | PNG → 阿里云OSS |
| L5 RAG | ≤30s | 向量嵌入 → Obsidian |
| L6 LibTV | ≤10min | 画布项目 |
| L7 审批 | 实时 | Approval Session |

**总 SLA**: 新视频出现 → 审批完成 ≤30min。

## 2. 埋点清单（11个核心监控点）

| ID | 采集点 | 指标 | 告警阈值 |
|----|--------|------|---------|
| M_L1_FETCH | 采集网关 | API耗时/状态码 | P95>5s, 错误率>5% |
| M_L1_NEW | 采集→Bitable | 新增/去重丢弃 | 连续3次空采集 |
| M_L2_COZE | Coze工作流 | 耗时/Token/状态 | >120s, error>0 |
| M_L2_XSCRIPT | 逐字稿提取 | 字数/成功率 | 字数<100 |
| M_L3_LLM | LLM分析 | 响应时间/Token | >60s |
| M_L3_SCORE | 质量评分 | 评分分布 | 低分率>30% |
| M_L4_IMAGE | 图文生成 | 成功率/图片大小 | 连续2次失败 |
| M_L5_VECTOR | Embedding | 延迟/索引大小 | >10s |
| M_L6_LIBTV | LibTV画布 | 耗时/节点数 | >60s |
| M_L7_APPROVE | 审批 | 延迟/通过率 | 通过率<60% |
| M_TOTAL | 全链路 | 端到端耗时 | >30min |

### 监控看板

- **链路健康度**：7段管道各自成功率 + QPS
- **成本仪表盘**：Coze/LLM/Embedding/OSS 日消耗
- **质量趋势**：通过率/评分/驳回率 周环比

## 3. 数据治理

### 3.1 去重

| 层级 | 去重键 |
|------|--------|
| 采集 | `巨量百应 video_id` → Bitable 唯一约束 |
| 分析 | `SHA256(逐字稿前500字)` → 复用历史结果 |
| RAG | `source_video_id` → upsert 更新版本 |
| 图文 | `MD5(图片二进制)` → 不重复上传 OSS |

### 3.2 质量标准

| 维度 | 检查 | 阈值 |
|------|------|------|
| 完整性 | 必填字段非空 | 100% |
| 逐字稿 | 字数≥100, 无乱码 | ≥95% |
| 分析深度 | 观点≥3, 引用≥3 | ≥80% |
| 图片质量 | ≥50KB, 分辨率合规 | ≥90% |
| 标签 | 人工抽检5%/周 | ≥85% |

### 3.3 生命周期

| 类型 | 活跃期 | 最终 |
|------|--------|------|
| Bitable | 7d热→30d温→90d冷 | >90d→OSS归档 |
| 逐字稿 | 7d | >30d删除(RAG已含) |
| 分析结果 | 7d→30d→180d | >180d→RAG保留 |
| 图文PNG | 30d→90d→1y | >1y删除(可重生成) |
| RAG向量 | 永久 | 永不过期 |
| 审批日志 | 30d→180d→2y | >2y匿名归档 |

### 3.4 RAG冷热分层

```
热: 7天 + 评分≥4 + 高频 → FAISS 内存索引 (全量搜索)
温: 7-90天 + 评分3-4  → HNSW 磁盘索引 (限域搜索)
冷: >90天 + 评分<3 + 零检索 → 压缩向量 + SQLite (仅关键词)
```

## 4. Obsidian RAG 知识库设计

### 4.1 三轴标签体系

```
类目: 电商带货/{日用百货|美妆护肤|食品饮料|服饰鞋包}
      知识科普/{科技数码|财经经济|健康医疗}
      生活记录/{亲子育儿|美食探店|旅行游记}
形式: 口播 | 剧情 | 评测 | 教程 | 开箱
质量: A级-优质 | B级-标准 | C级-基础
```

### 4.2 目录结构

```
content-mid-platform/
├── _meta/_index.md + tag-taxonomy.md + embedding-config.json
├── by-category/{类目}/{子类}/
├── by-quality/{A级|B级|C级}/
├── analysis-results/{YYYY-MM-DD}/{video_id}.md
└── templates/analysis-template.md
```

### 4.3 RAG Entry 元数据

```json
{
  "id": "rag_xxx",
  "title": "视频标题",
  "video_id": "jlb_xxx",
  "author": "博主名称",
  "category": "电商带货/美妆护肤",
  "tags": ["类目:电商带货/美妆护肤", "形式:口播", "质量:A级"],
  "quality_score": 4.2,
  "view_count": 5,
  "embedding_model": "text-embedding-3-small",
  "embedding_dim": 1536,
  "created_at": "2026-07-10T08:00:00Z",
  "expire_at": "2026-10-10T08:00:00Z"
}
```

### 4.4 检索策略

| 场景 | 方式 | 参数 |
|------|------|------|
| 选题 | 语义 top-K | k=10, threshold=0.7 |
| 查重 | 精确+语义近似 | threshold=0.92 |
| 推荐 | tag过滤+语义排序 | 先过滤再排序 |
| 趋势 | 聚合(类目+时间) | group by, count>5 |

## 5. 数据闭环

### 5.1 采集策略自动调优

| 反馈信号 | 调整 | 条件 |
|---------|------|------|
| 某类目通过率>85% | +20%配额 | 持续3天 |
| 驳回率>40% | -50%权重 | 持续2天 |
| 博主持续低分(<3) | 黑名单 | 连续5条 |
| 博主持续高分(>4.5) | 白名单 | 连续3条 |
| 短视频(<30s)低分 | 设最小时长 | 累计10条 |

### 5.2 运营目标

| 指标 | 定义 | 目标 |
|------|------|------|
| 采集效率 | 入库数/API调用 | ≥80% |
| 分析转化率 | 完成数/提交数 | ≥90% |
| 图文通过率 | 通过数/审批数 | ≥75% |
| 知识利用率 | RAG命中数/入库数 | ≥60% |

## 6. 存储成本

### 6.1 数据量

| 类型 | 日增量 | 年增量 |
|------|--------|--------|
| Bitable记录 | 400KB | 144MB |
| 逐字稿 | 2.25MB | 810MB |
| 分析结果 | 1.5MB | 540MB |
| 图文PNG | 60MB | 21.6GB |
| RAG向量+文档 | 3MB | 1.1GB |
| LibTV画布 | 120MB | 43.2GB |
| **合计** | **~187MB/日** | **~67.5GB/年** |

### 6.2 月成本(~¥70)

| 项目 | 月成本 |
|------|--------|
| 飞书Bitable | ¥0 |
| 阿里云OSS标准 | ¥3.50 |
| OSS流量 | ¥15 |
| OSS归档 | ¥1.50 |
| LibTV订阅 | ~¥30 |
| SLS日志(可选) | ¥20 |
| 本地存储 | ¥0 |

### 6.3 优化建议

- PNG→WebP → 存储-70%
- 评分<3.5跳过图文 → 图片量-20%
- 零检索RAG清理 → 体积-30%
- 草稿画布14天自动清理 → 存储-40%
