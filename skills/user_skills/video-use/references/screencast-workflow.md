# 口播+录屏视频剪辑工作流（AI 工具经验分享博主适用）

## 用户画像

AI 生成图片/视频的 **经验分享自媒体博主**。视频形式：
- **画面**：电脑录屏（ComfyUI / Midjourney / Stable Diffusion 操作过程）
- **音频**：全程口播讲解
- **痛点**：口误多、多条 take、手动剪辑费时
- **平台**：抖音 / 小红书（竖屏 1080×1920）

## video-use 在这个场景中的职责

video-use **不**做 AI 生图（你已有工具），**不**生成配音（你已自己录）。它做的是：

- 把多条 take 自动拼接成一条完整视频
- 去掉口误、填充词（呃、那个、就是）
- 给每段画面做自动调色（录屏色温一致性）
- 交叉口播和画面对齐
- 加字幕（中文字幕同步口播）
- 30ms 音频淡入淡出防爆音

## 标准工作流

### 第 1 步：准备素材

把你为同一期视频录制的所有原始素材放进 **同一个文件夹**：

```
D:\videos\2026-07-18-comfyui-workflow\
├── take1_intro.mp4       # 开场介绍
├── take2_demo_good.mp4   # 演示过程（讲得顺的一遍）
├── take3_demo_stumble.mp4 # 演示过程（有口误）
├── take4_outro.mp4        # 结尾总结
└── take5_bonus_tip.mp4    # 额外小技巧
```

> 命名规则不重要——能区分 take 就行。video-use 会转录后自动理解内容。

### 第 2 步：指挥剪辑

在素材目录下启动会话，说：

> "帮我把这些剪成一条 5-8 分钟的教程视频，去掉口误和废话，竖屏，加中文字幕。"

AI 会：
1. 对所有素材做语音转录（Scribe）
2. 打包成可阅读的文本结构
3. 提出剪辑策略（用哪些段落、怎么拼接）
4. 等待你确认
5. 执行剪辑
6. 自检（检查画面跳跃、音频爆音、字幕遮挡）
7. 输出 `edit/final.mp4`

### 第 3 步：审核与迭代

- 预览 `edit/preview.mp4`
- 反馈："开头节奏太慢，剪掉前面 5 秒"/"中间演示部分用 take2 不要 take3"
- AI 重新渲染
- 确认后导出

## 典型场景的提示语

### 场景 A：一条过（只有一段完整录屏）

> "帮我把这段录屏整理一下，去掉所有的'呃'和'那个'，加字幕，2 分钟内。"

### 场景 B：多条 take 选最佳

> "这 3 个文件是同一期视频的不同录制，帮我把最好的段落拼在一起，去掉重复内容，5 分钟左右。"

### 场景 C：混合素材

> "这段录屏是演示过程，这段是口播特写，帮我把它们拼接成交替使用，中间加 200ms 过渡。"

### 场景 D：重点标注

> "在 1:23 的地方画面左上角加一个橙色箭头标注 3 秒，提示观众看那个参数设置。"

## 技术注意事项

- **分辨率**：录屏一般是 1920×1080，抖音竖屏需要 1080×1920。在 EDL 或策略阶段指定。
- **帧率**：录屏常见 30fps，AI 生图演示素材可能帧率不一。video-use 的 `render.py` 会统一。
- **字幕语言**：Scribe 支持中文，转录中文口播没问题。
- **ElevenLabs API Key**：必须预先配好。Scribe 转录是按用量计费的（有免费额度）。
- **素材时长**：长视频（>30 分钟）转录可能耗时较长。建议控制在 5-15 分钟以便快速迭代。
- **口误标记**：Scribe 会自动标记填充词。需要在策略阶段告诉 AI "去掉所有填充词"。

## 已知限制

1. video-use 不生成配音——口播必须自己录并存为视频文件
2. video-use 不运行 ComfyUI/Midjourney——画面必须是已有录屏
3. 不会自动检测画面中的 UI 变化——只处理音轨对口
4. 动画叠加层（箭头、标注）需要 EDL 手动指定时间点
5. 中文填充词识别效果取决于 Scribe 的标记能力

## 与现有工具链的配合

```
    ↕ (录制 .mp4)

    ↕

```
