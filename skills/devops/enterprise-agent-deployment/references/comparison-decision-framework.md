# Agent 协作方案对比决策框架

> 三种跨 Agent 协作方案的核心差异与选择逻辑。
> 适用于：需要评估不同 Agent 集成方案时的决策参考。

## 三方案对比

| 维度 | PAF（文件基座） | A2A（网络协议） | agents-hive（框架） |
|------|---------------|---------------|-------------------|
| **本质** | 共享文件目录 | HTTP REST 实时通信 | 任务调度引擎 |
| **Agent 怎么连** | 读同一份 GLOBAL/ 文件 | 互调 API（SendMessage/GetTask） | 框架内编排 |
| **同步什么** | 上下文、规则、账号路由 | 任务（Task）、消息、产物 | 任务 + Agent 状态 |
| **实时性** | 一次性安装，运行时不通信 | 实时请求/响应/流式推送 | 框架内实时调度 |
| **Agent 关系** | 松散耦合，各自独立 | Client-Server 紧密耦合 | 框架内编排耦合 |
| **Skill 共享** | SKILL_DEPENDENCIES.md 清单 | AgentCard 声明能力 | 框架内注册 |
| **会话同步** | 不涉及 | 不涉及 | 框架内管理 |
| **数据主权** | 文件在本地，完全可控 | 各自保管 | 框架内流转 |
| **对 Agent 要求** | 能读文件目录即可 | 必须实现 A2A HTTP 端点 | 必须接入框架 |
| **WorkBuddy 适配** | 直接读文件 | 需建适配网关 | 需要框架适配器 |
| **成熟度** | 新项目，有脚手架 | v1.0.1 正式版，25k⭐ | 未公开（私有） |
| **适用场景** | 换 Agent 不丢配置 | 多 Agent 实时协同干活 | 复杂任务调度编排 |

## 决策树

```
你想解决什么问题？
│
├── "换 Agent/设备时不想重新配置一切"
│   → PAF（文件基座）
│   → 装 GLOBAL 模板，跑 install-agent-scaffold
│   → 适合：个人用户、小团队、跨客户端迁移
│
├── "多个 Agent 要实时互相调用、协同干活"
│   → A2A（网络协议）
│   → 实现 A2A HTTP 端点 + AgentCard
│   → 适合：需要实时协作的异构 Agent 网络
│
├── "复杂的任务调度，一个 Agent 编排多个子 Agent"
│   → 框架方案（agents-hive / LangGraph / CrewAI）
│   → 适合：框架内编排，不需要跨框架互操作
│   → 注意：你的 Hermes 已有 orchestrator-loop + Kanban + delegate_task
│
└── "已经在用 Hermes，需要扩展"
    → 先检查现有能力：
       • delegate_task = 同 Profile 内子任务
       • Kanban = 跨 Profile 异步调度
       • orchestrator-loop = 五阶段复杂任务编排
       • three-agent-orchestrator = Hermes+OpenCode+Coze
    → 如果现有能力不够，再考虑引入新方案
```

## 核心原则

### 1. 不要用新框架替代已有系统

你的 Hermes 环境已经跑了 100+ 个 Skill、6 个 Profile、Kanban + delegate_task + 三Agent 编排。换框架的成本 > 在现有框架上优化的成本。

### 2. 三层叠加优于二选一

```
┌──────────────────────────────────────────────────┐
│ 上层：实时协作（A2A 协议，可选）                    │
│ 中层：任务编排（Hermes delegate_task/Kanban）      │
│ 下层：统一规则（GLOBAL 共享底座）                    │
└──────────────────────────────────────────────────┘
```

下层保证"换 Agent 不丢人设"，中层保证"单 Agent 内有序编排"，上层保证"多 Agent 实时协同"。三者不冲突，互补。

### 3. 开源的才是可用的

agents-hive 不开源就不能用。PAF 和 A2A 都开源，可以直接用。

## 对你现状的评估

| 你的需求 | 现有方案 | 是否需要新方案 |
|---------|---------|--------------|
| 换设备不丢配置 | GLOBAL 模板（已创建） | ❌ 不需要 |
| 多 Agent 实时协作 | delegate_task + Kanban（已够用） | ❌ 不需要 |
| 复杂任务编排 | orchestrator-loop（已够用） | ❌ 不需要 |
| 跨部门隔离 | 企业级 Hermes 底座（已创建） | ❌ 不需要 |
| Token 管理 | 脚本已就绪 | ❌ 不需要 |

**结论：你现有的 Hermes 环境已经比任何一个社区项目完整。新框架的价值在于启发，不在于替代。**
